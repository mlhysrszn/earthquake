# Project Working Agreement

## Scope and documentation

- Work in small steps using `docs/ROADMAP.md`.
- Maintain all project documentation in English. Conversation may remain Turkish.
- Follow `docs/ARCHITECTURE.md` and `docs/DATA_CONTRACT.md`.
- Use Hilt as specified in the architecture; follow official Android guidance.

## Verification and commits

- Verify each completed step with the relevant tests, build, and manual checks.
- Report the changes, actual verification results, and remaining limitations.
- Wait for the user's explicit approval before every commit. Approval to start
  work, initialize Git, or run tests does not authorize a commit.
- After approval, commit only the reviewed scope. If that scope changes, verify
  the new changes and request approval again before committing.
- Aim for one focused commit per completed roadmap task or explicitly agreed
  small batch. Stop at the approval checkpoint before starting the next batch.
- Do not publish, push, or create a remote repository without authorization.
- Keep local configuration, credentials, signing keys, and build output out of Git.

## Records

- Update the roadmap and `docs/WORK_LOG.md` with actual results.
- Keep `docs/AI_USAGE_REPORT.md` factual. Label estimates and unavailable data.
- Do not mark blocked or unverified tasks complete.
